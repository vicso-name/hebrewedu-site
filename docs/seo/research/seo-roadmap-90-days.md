# HebrewEdu SEO Roadmap — 90 Days

Planning horizon: 90 days from approval. No work below implies permission to publish; all content edits require the appropriate product/editorial review. Prioritize existing pages before net-new content. Baselines are incomplete: GSC exports are aggregate Web without reliable US/mobile query-to-URL attribution, and the SERP pilot is a one-day sample.

## Days 1–14 — Measurement and technical/indexing baseline

**Technical/indexing**
- Verify indexability, canonical URL, sitemap inclusion, robots access, rendered title/H1 and internal links for the homepage, `/play/`, alphabet guide, difficulty article, 7-day guide, Nikud guide, without-vowels guide, vocabulary article, root/Binyanim pages, and any public verb resource.
- Confirm whether `/play/` game routes are crawlable and have stable canonical destinations; verify app-store links and platform messaging on the homepage. This is verification work, not a claim of an existing defect.

**Measurement**
- Export GSC Search Analytics by page/query for the same 90-day baseline, separating US where data permits and Web/mobile device dimensions where available. Save clicks, impressions, CTR, position, page, query, country, device. Preserve low-volume/privacy-filtered gaps as unavailable.
- Establish rank tracking for the 36 representative queries in `rank-tracking-keywords.csv`: Google US, English, mobile Android. Record date/device/location and keep baseline blank until a rank measurement is actually captured.
- Resolve instrumentation and indexability for the existing browser games and app landing path.

**Dependencies:** access to verified Search Console property, analytics/rank measurement tool, confirmed canonical URL inventory.

**Checkpoint / success criteria:** baseline dataset saved with segment definitions; target URLs return the expected canonical/indexable state; all unknowns logged instead of assumed.

## Days 15–35 — Improve high-confidence existing targets

**Content improvements**
- Alphabet guide: make the 22-letter table mobile-scannable; confirm names/sounds; clarify what “pronunciation” covers; add contextual links to the 7-day guide and genuine play/app destinations. Validate a chart visual before claiming chart/printable coverage.
- Without-vowels article: distinguish spoken vowel sounds from written vowel points, define Modern Hebrew scope, and cross-link to Nikud guide.
- Nikud guide: clarify the pointed-text learning task and add/verify a concise worked example; distinguish it from unpointed reading.
- Vocabulary method article: clearly signal it teaches learning methods rather than presenting a frequency list; link to the actual vocabulary feature without overstating web functionality.
- Homepage: make the actual alphabet-first beginner product, current platforms, app-store paths, and features explicit. Avoid comparison claims unless evidence exists.

**Dependencies:** editorial/product fact-check; current iOS/Android capability confirmation; GSC baseline.

**Checkpoint / success criteria:** approved edits are live only after separate publication authorization; page-to-query mapping has one primary destination for each intent; no unsupported claims; crawl and canonical checks pass.

## Days 36–60 — Validate weak targets and format gaps

**Content / format validation**
- Compare the two failed pilot queries (`learn hebrew for beginners`, `is hebrew hard to learn`) with successful US mobile SERPs before changing mappings.
- Recheck SERP formats for app selection, alphabet chart, broad “how to read Hebrew,” Nikud, vocabulary, and grammar; use current representative dates and preserve exact target URLs.
- Verify whether the verb directory is a public, indexable web tool or an app-only feature. Validate browser game routes against actual play experience.
- Review keyword overlap via GSC page/query pairs after baseline; resolve cannibalization only when evidence shows multiple URLs compete for the same intent.

**New content opportunity gate (planning only):** app-selection/comparison page, downloadable/visual alphabet chart, common-word list, or broad beginner grammar page require validated SERP format, distinct user need, sourceable claims/data, and a clear reason existing pages cannot satisfy it. Do not create pages solely because semantically similar keywords exist.

**Checkpoint / success criteria:** each candidate gap has evidence, existing-page alternative, proposed format and owner; decisions are Go/No-go; no unsupported page brief is advanced.

## Days 61–90 — Measure, refine and decide next cycle

**Measurement**
- Compare page/query impressions, clicks and CTR against the saved baseline using the same filters; segment US/mobile when sample sizes permit. Report missing/filtered data explicitly.
- Review rank-tracking measurements for the selected 36 queries; compare like-for-like US/English/mobile/Android settings and annotate snapshot date. Do not treat a single observed rank as stable.
- Check whether the observed `hebrew alphabet app` rank-7 snapshot recurs in subsequent measurements; do not label it a persistent baseline until repeated tracking confirms it.

**Technical/indexing**
- Verify recrawl/index state for any approved updated page and inspect canonical/sitemap/internal-link consistency.

**Checkpoint / success criteria:** report movement using measured GSC/rank data only; retain, revise, or retire target assignments with evidence; decide whether any new content brief meets its gate.

## Workstream separation and dependencies

| Workstream | First priority | Dependency | Success measure |
|---|---|---|---|
| Technical/indexing | Verify canonical, indexability, sitemap and game/app routes | Site/Search Console access | Expected URLs are accessible and indexable; issues documented |
| Existing content | Improve alphabet, reading/Nikud, without-vowels, vocabulary scope and homepage claims | Editorial and product review | Clear intent scope, accurate features, clean target mapping |
| New content | Validate app-selection, chart/list/grammar formats before briefing | SERP and product evidence; separate approval | Distinct evidenced need; no cannibalizing current targets |
| Measurement | GSC segmented baseline and consistent mobile Android rank tracking | Verified properties/tool configuration | Dated comparable baseline with blanks for unmeasured data |

No API calls, website changes, publication, commit or push are part of this planning deliverable.
